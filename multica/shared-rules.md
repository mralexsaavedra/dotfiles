- User-level skills, ~/.claude config and ~/Developer/dotfiles/bin come from the dotfiles repo (~/.claude/skills is a symlink into ~/Developer/dotfiles/claude-code/.claude/skills). If you change one, do it there and commit it with a conventional commit and push to main of dotfiles, as the owner does; never leave it uncommitted, because the other machine pulls dotfiles every weekday morning. Skills that live inside a project repository (its own skills/ or .claude/skills) follow that repository's branch and PR rules instead.
- Use gh for everything GitHub (PRs, checks, issues, API).
- After opening a pull request, link it to this Multica issue with `multica-link-pr <issue> <pr-url>` (in ~/Developer/dotfiles/bin). If it links, follow it with `multica issue wakeup create <issue> --until-pr checks|merged`. If it exits 3 (the repository is not in the Multica GitHub App: today only the owner's account and lookiero/sty-sp-front), use a timed wakeup instead (`--kind at --after 30m`) and check with `gh pr view`/`gh pr checks`, rescheduling while pending (max 12).
